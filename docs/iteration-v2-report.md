# 制作指示書 Ver.2 改良報告 — v0.8

EP001にだけ、現在の夜の寝室を追加しました。導入・OP曲の3秒遅延・認証・端末・記憶の本文・各件の不可逆な選択・結末は維持しています。

## 試す

公開先：https://onigiri-mentai.github.io/fadeout-selfservice/?v=0.8

1. 音の案内から始め、端末の「記憶の履歴確認・消去」→001→「対象者の現状を確認する」へ進みます。「記憶を確認する」も初回は現状確認へつながります。
2. 絵の下の手を背中へドラッグします。指を動かし続けても、描かれた手は近くで止まります。放すと「触れられない」と返ります。タップ、またはボタンのEnter／Spaceでも試せます。
3. 「窓辺に手を伸ばす」で布と呼吸の微かな変化を見ます。窓辺を先に試してから背中へ手を伸ばしても成立します。スマートフォンは反応せず、短いドラッグの取りやめにも文章が返ります。
4. 「過去の記憶を確認する」で、既存の黒鉛筆画の001へ進みます。現状確認で全操作を行う義務や待ち時間はありません。目安は、反応を読んで30秒〜2分程度です。
5. 既存の椅子・カップ・手・椅子の再調査を経て、その記憶の消去／保持を選びます。

ローカルは `python3 -m http.server 8000` のあと `http://localhost:8000`。ビルドせず動きます。

001が未確定なら、以前のセーブからも新しいボタンへ入れます。確定済みの場合は過去の記録閲覧を維持し、現在の場面を「消去後の結果」として後付けしません。新規に試すには別のブラウザ、または設定の確認付きリセットを使ってください。

## 保存の扱い

保存キー `fadeout.prototype.v1`、`version: 1`、`flowVersion: 2` は維持しています。既存の `memories`・`completed`・`choices` はそのまま復元し、欠けている `present001` だけを未体験として補います。古い記憶探索の途中を、新パートの冒頭へ強制的に戻すこともありません。

追加項目は、入場／終了、背中・窓辺・小物の試行回数（内部保存だけで上限9、画面には表示しません）、近づいた状態、最後の反応です。操作の点数や能力・風のゲージではありません。演出の途中からの再開時は、最後の反応を静かに復元し、嗚咽を自動で繰り返しません。

## 仮の部分と未決定事項

- 「午前二時十七分」はこの現状場面の仮題・仮時刻です。「空いた席」の正式改題ではありません。
- 写真風の寝室は生成した差し替え素材です。肩・カーテンの動きは画像の一部を重ねる仮演出です。本番では別レイヤーの作画・連続した肩や布の動きの制作が必要です。
- 画面の手は操作位置を示す線画です。主人公の身体や、自由に物へ干渉できる能力の確定ではありません。スマホは反応せず、相手も主人公に気づきません。
- 嗚咽／吐息は短い合成した息の音です。人の声を録音した素材ではありません。最初の一回だけ短く鳴り、再開時や閲覧中に長い泣き声を強制しません。風も合成音です。本番の泣き声・布・夜の環境音は要制作です。
- 相手はまだ泣いており、悲しみは解決していません。風が主人公の行為で生じたか、自然に吹いたかは断定していません。人物関係・名前・死因、4件の対象者が同一かどうか、消去の影響範囲は決めていません。
- 現状の試作では、写真風の現在→鉛筆画の記憶の切り替わりが大きく感じられる可能性があります。この質感の差と、反応しない操作の繰り返しが負担にならないかが主な試遊ポイントです。探索条件を増やすための必須操作にはしていません。

## 検証と限界

Chromiumで、手のドラッグ・タップ・Enter／Space、逆順、再タップ、反応しない小物、自由な終了、音OFF・音量・字幕・動き軽減、幅320／390／1365px、途中の保存・再開、現在→記憶→既存の選択と次の解放を確認しました。既存のOP再生・3秒待ち・認証停止、導入の再開、ボタン内ノイズ、4件の進行と結末も回帰確認済みです。

iPhone／Safari実機、VoiceOver、実際の指での届かなさ・風の心地よさの評価は未検証です。モバイル幅とタッチイベントの自動確認は、実機確認の代替ではありません。感じ方の評価は制作者の試遊が必要です。

## 選択の不可逆性：今回変えていない3方式の比較

| 方式 | 体験と注意点 | 変える場合の技術・保存への影響 |
| --- | --- | --- |
| 現行：各EPで消去／保持を確定 | その場で選ぶ重みがある。後の記憶を見て気持ちが変わっても、確定した選択には戻れない | 今回のまま。既存 `choices` と確定後の解放を維持 |
| 仮指定：消去候補／保持候補／保留、最後に実行 | 後から迷い直せる。最後の実行が単なる確認作業にならない見せ方が必要 | `draftChoices` などの仮指定と実行済みを分け、解放・確認画面・結末判定を変更。旧セーブの確定済み選択を勝手に仮指定へ戻さず、旧方式の継続か新規プレイへの適用を選ぶ移行が必要 |
| 全履歴後に最終決断 | 流れが単純。各EPの途中で何を確かめたくなるかを別途設計する必要 | 次の解放を `choices` から閲覧完了へ分離。最終決断の範囲と保存を追加し、既存のEP別の確定結果とは区別する移行が必要 |

この3案は比較だけです。今回は選択方式・取り消し・消去の世界設定を変更していません。
