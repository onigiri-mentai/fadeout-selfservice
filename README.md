# フェードアウトはセルフでお願いします。

雰囲気と記憶探索の操作感を検証する、静的ブラウザゲーム試作品 v0.8.2です。
HTML / CSS / JavaScriptだけで動きます。実行時の外部通信・API・ログイン・サーバー処理はありません。

ソースコード：https://github.com/onigiri-mentai/fadeout-selfservice

GitHub Pagesでの試遊先（Pagesの公開設定後）：https://onigiri-mentai.github.io/fadeout-selfservice/

## 冒頭演出

最初に音の案内で再生設定を選ぶと、黒い全画面のモノローグ→白い空間にある受付機のアップ→モニターへの接近→白い画面のタイトルロゴへ進みます。中央下部のグレーとホワイトの「認証する」で、ぐるぐるの「認証中」→チェックマークの「認証済み」に切り替わります。「利用案内へ」を押して原文の利用案内へ進み、「確認しました」で操作画面へ進みます。黒いモノローグは手動送り、受付機のアップからタイトルまでは自動です。タイトルと認証済み画面は、ボタンを押すまで表示を保ちます。最後の一文は「そう思って、私はここに来た。」に変更し、利用案内と既存の記憶の本文は維持しています。導入中はサイトのヘッダー・フッターを表示しません。

黒いモノローグは画面タップ／Enter／Spaceで次へ進みます。受付機が現れてからは「タップして次へ」を表示せず、自動で進みます。右上から案内へスキップできます。OSまたはゲーム内の動き軽減が有効な場合、ズームと文字のアニメーションを止め、静止画を切り替えます。バックグラウンドでは演出と自動進行を一時停止します。

背景は今回生成した仮の建築ビジュアルです。PC用・スマホ縦用に同じ意匠の受付機を用意し、それぞれ一枚の画像を使用します。最初の受付機は従来のズーム後の位置に固定し、遠景からのズームは行いません。モニターへは小さく寄り、淡い白へのディゾルブでつなぎます。タイトルロゴは自動では消えず、ボタン操作を待ちます。認証は約2秒のゲーム内演出で、個人情報入力・外部認証・ログインは行いません。認証中と認証済みも保存して再開できます。3D移動や動画ではなく、CSSのカメラ移動です。構図・表示面の位置・各場面の秒数は`intro.js`で調整できます。

保存形式のバージョンとキーは維持し、導入の場面・モノローグの位置だけを追加で保存します。v0.2以前のセーブも引き継ぎ、利用案内の確認済みの人は音の案内を確認後、保存した画面から再開します。**既に遊んだ人は「設定 → 冒頭の演出をもう一度見る」で、進行を消さずに新しい冒頭を見られます。**

参考HTMLの年齢・性別入力、記憶残存率スライダー、記憶編集機能、セリフ「ここは……？」は取り入れていません。

## 動かす

一番手軽な方法は、`index.html`をブラウザで開くことです。ビルド不要です。ただし、`file://`での保存の扱いはブラウザにより異なります。

ローカルサーバーを使う場合は、プロジェクトのフォルダで次を実行します。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開いてください。Node.jsがある場合は `npm start` でも起動できます。ゲームを動かすための `npm install` は不要です。

スマホでは同じWi-Fi上のPCのIPアドレスとポート、またはホスティングしたURLを開きます。

## 操作

1. 最初に音をオンにするか、音なしにするかを選びます。初回は黒いプロローグを表示し、文章はタップで進めます。受付機のアップからモニターへの接近は自動です。タイトルの「認証する」→認証済みの「利用案内へ」で進み、利用案内を確認してください。右上から案内へスキップすることもできます。
2. 受付機の「記憶の履歴確認・消去」を開き、エピソードを選びます。手続き画面の「記憶を確認する」で探索に入ります。
3. 絵の丸い印をタップ／クリックして調査します。スマホでは左右に動かして見られ、「全体を見る」で絵全体も確認できます。画面下の「調べる場所の一覧」を開いて選ぶ方法もあります。
4. 関連する断片を見ると、前に調べた場所の反応が変わります。「ヒント・表示」を開き、「次の手がかりを確認」で進め方を確認できます。
5. 必須の断片を確認すると「消去するか選ぶ」が有効になります。押すと、そのエピソードの手続き画面へ戻ります。カレンダーなど任意の調査は必須ではありません。
6. 「この記憶を消去する／この記憶を残す」を選び、確認ダイアログで確定します。結果画面から次のエピソードへ進みます。004の選択後は、4件の結果と仮エンディングを表示します。

Tabで移動、Enter／Spaceで操作。設定ダイアログはEscで閉じられます。進行はブラウザ内に自動保存し、次回アクセス時は音の案内を確認してから、保存した場面から再開します。設定から冒頭だけを再生したり、進行を初期化したりできます。保存不可でもその場で遊べます。

最初の案内で音ON／音なしを選べます。冒頭と通常画面の右上から切り替えられ、設定で音量を変えられます。重要な音には字幕があります。OSの動き軽減設定と、ゲーム内の動き軽減設定に対応します。

## 実装した範囲

- 短いプロローグと、原文のご利用案内（読み返し可）。
- ATM風の受付機と2ボタンのトップメニュー。各エピソードの確認前は、消去ボタン内だけにノイズが返ります。
- 最初から見えている4件の枠と、各エピソードの選択による001→004の順番解放。手続き前の記録の再訪。
- **001「空いた席」**：椅子、マグカップと輪染み、カレンダー、食器を片づける手。椅子とカップを見たあとで手を調べると、二枚目の皿へ指が伸びて止まり、生活音が途切れ、カップに淡い青灰色が差します。その後の椅子の再調査で文章と音の意味が変わります。手を先に調べた場合も詰まりません。
- **002〜004**：各4箇所の短い探索。スマホ／スプーン／小皿の再調査と、限定した色・線の変化。各件を完了できます。
- 各エピソードの確認・消去／保持・結果画面。4件の選択一覧と、全件消去・全件保持・一部消去の仮エンディング。
- 自動保存、再開、音量・ミュート、動き軽減、ヒント、キーボード操作、確認付きリセット。

旧案の人間職員・同行制度は登場しません。主人公の死因・名前・具体的な人物関係は設定していません。

## 仮の部分・制作上の限界

002〜004の具体的な本文・小物・共通性、手続き結果の補足、各エンディングは検討用の仮案です。完成シナリオとして確定していません。001の後続文も操作検証のための案です。

画像は今回生成した、顔の映らない黒鉛筆画の**差し替え用仮イラスト**です。最終画風の確定稿ではありません。色鉛筆・輪染み・手の動きはSVG／CSSの重ね合わせによる仮演出で、実際に食器を持ち替える連続作画は未制作です。002のスマホ画面の文章は調査欄で表現します。

冒頭のBGMは提供されたMP3、操作音・生活音はWeb Audioの合成音です。生活音の質感と静寂の間を試すためのもので、実録の環境音や声優音声・笑い声の録音は未実装です。言葉や笑いの内容は字幕で伝えます。端末の低い音は、スピーカーによって聞こえ方が異なります。

ブラウザでの自動確認はChromiumで実施しました。Safari／iOS実機、VoiceOverなどでの最終確認、人物・小物の連続性を保つ本番アセット制作は今後の作業です。

各調査点の`base`が最初の反応、`variants[].when`が反応を変える前提断片、`grant`が再調査で得る断片です。通常の再調査はその場所を一度見ていることも条件になります。001の手のように前提が必要な箇所には`blocked`を設定します。`required`の断片が揃い、「消去するか選ぶ」を押すと確認済みになります。次のエピソードの解放は、`engine.js` の `choose()` でその記憶の選択を確定した時点です。

調査位置`x`・`y`は絵の幅・高さに対する百分率です。背景を個別画像にする場合は`data.js`の`image`を変更し、`main.js`の背景サイズを`100% 100%`にします。画像とSVGの座標を揃えてください。進行データの互換性が変わる場合は保存キー／バージョンを更新するか、設定からリセットします。

## GitHub Pages

全て相対パスなので、リポジトリ名の付いたURLでも動きます。

**ビルドなし（推奨）**：Settings → Pages → Deploy from a branchで`main`ブランチと`/(root)`を選び、Saveを押します。Pagesの設定でプランによる制限が出る場合は、Settings → General → Danger Zone → Change repository visibilityでPublicに変更してから設定してください。通常、数分で上記の試遊URLから遊べます。

**GitHub Actionsを使う場合**：Settings → PagesのSourceをGitHub Actionsにし、付属の「Deploy browser prototype to GitHub Pages」を手動実行します。テスト→静的ファイルのビルド→`dist/`の配信を行います。自動pushトリガーは付けていません。ソース一式はGitHubへ反映しています。リポジトリの公開範囲とPagesの有効化は、GitHubの設定画面で管理します。

他の静的ホスティングでは、次で生成した`dist/`だけを配信できます。

```sh
npm test
npm run build
```

現状確認のブラウザテストでは、丸印のタップ・キーボード・開閉式の一覧、触れられなさと風の反応、再タップ・逆順、待機不要、途中再開、音量・ミュート・字幕・動き軽減、現在→記憶→既存選択、002以降の維持を確認します。

音のブラウザテストでは、初期画面が無音であること、タップでの実MP3再生、ループ、タイトルまでの再生、認証ボタンでの停止、操作音、ミュート・音量、タブ移動と復帰、再読み込み・冒頭の再生・スキップ、幅320pxの案内を確認します。

導入のブラウザテストでは、黒い文章がタップまで読めること、黒いプロローグ直後からズーム後の位置で表示され、遠景と最初のズームがないこと、そこから自動で進み送り表示が出ないこと、背景タブでの一時停止・再開、接近が控えめであること、白い画面の中央に収まるタイトルロゴ、中央下部のボタン、認証中のスピナー・認証済みのチェック、認証状態の保存・再開、確認済み利用者も案内へ進むこと、タップ・スキップ、動き軽減、縦画面の構図、導入途中の再開、進行を保つ再生、旧セーブの移行、リセットを確認します。

読みやすさ・ノイズのテストでは、補足文字の最低14px、ボタン内だけでランダムに変化するノイズ、外側の画面が動かないこと、動き軽減で更新が止まること、履歴への遷移と解放後にノイズが除かれること、幅320pxでの表示を確認します。

`npm run test:browser`：開発環境にPlaywrightとChromiumを用意し、先にローカルサーバーを起動して実行します。実行時依存には含めていません。`GAME_URL`（既定 `http://127.0.0.1:8000`）と`CHROMIUM_PATH`（既定 `/usr/bin/chromium`）で変更できます。2ボタンの配置・各件の確認と選択・混在した結果・従来の両結末・再開・設定・キーボード・幅320/390/1365を確認し、`test-results/`へ画像を保存します。
