# フェードアウトはセルフでお願いします。

雰囲気と記憶探索の操作感を検証する、静的ブラウザゲーム試作品 v0.1です。
HTML / CSS / JavaScriptだけで動きます。実行時の外部通信・API・ログイン・サーバー処理はありません。

ソースコード：https://github.com/onigiri-mentai/fadeout-selfservice

GitHub Pagesでの試遊先（Pagesの公開設定後）：https://onigiri-mentai.github.io/fadeout-selfservice/

## 動かす

一番手軽な方法は、`index.html`をブラウザで開くことです。ビルド不要です。ただし、`file://`での保存の扱いはブラウザにより異なります。

ローカルサーバーを使う場合は、プロジェクトのフォルダで次を実行します。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開いてください。Node.jsがある場合は `npm start` でも起動できます。ゲームを動かすための `npm install` は不要です。

スマホでは同じWi-Fi上のPCのIPアドレスとポート、またはホスティングしたURLを開きます。

## 操作

1. 「受付機を起動する」→プロローグ→ご利用案内。「受付機へ」で待たずに進むこともできます。
2. 受付機の「記憶の履歴」を開き、閲覧可能な履歴を選びます。
3. 絵の丸い印をタップ／クリックして調査します。「調べる場所を一覧から選ぶ」でも操作できます。
4. 関連する断片を見ると、前に調べた場所の反応が変わります。「少しだけヒントを見る」で次の手がかりを確認できます。
5. 必須の断片を確認すると「閲覧を終える」が有効になります。押すと次の履歴が読み込まれます。カレンダーなど任意の調査は必須ではありません。
6. 004を終えると受付機へ戻ります。消去ボタンのノイズが止まり、「消去する／消去しない」の手続きへ進めます。最終選択は確認画面を挟みます。

Tabで移動、Enter／Spaceで操作。設定ダイアログはEscで閉じられます。進行はブラウザ内に自動保存し、タイトルの「続きから」で再開できます。設定から初期化できます。保存不可でもその場で遊べます。

音は初期状態でOFF。右上からONにでき、設定で音量を変えられます。重要な音には字幕があります。OSの動き軽減設定と、ゲーム内の動き軽減設定に対応します。

## 実装した範囲

- 短いプロローグと、原文のご利用案内（読み返し可）。
- ATM風の受付機。触れると短くノイズが返る、序盤は進めない消去ボタン。
- 最初から見えている4件の枠と、001→004の順番解放。閲覧済みの再訪。
- **001「空いた席」**：椅子、マグカップと輪染み、カレンダー、食器を片づける手。椅子とカップを見たあとで手を調べると、二枚目の皿へ指が伸びて止まり、生活音が途切れ、カップに淡い青灰色が差します。その後の椅子の再調査で文章と音の意味が変わります。手を先に調べた場合も詰まりません。
- **002〜004**：各4箇所の短い探索。スマホ／スプーン／小皿の再調査と、限定した色・線の変化。各件を完了できます。
- 004終了後に静かになる受付機、照合画面、二つの仮エンディング。
- 自動保存、再開、音量・ミュート、動き軽減、ヒント、キーボード操作、確認付きリセット。

旧案の人間職員・同行制度は登場しません。主人公の死因・名前・具体的な人物関係は設定していません。

## 仮の部分・制作上の限界

002〜004の具体的な本文・小物・共通性、最終確認文、両エンディングは検討用の仮案です。完成シナリオとして確定していません。001の後続文も操作検証のための案です。

画像は今回生成した、顔の映らない黒鉛筆画の**差し替え用仮イラスト**です。最終画風の確定稿ではありません。色鉛筆・輪染み・手の動きはSVG／CSSの重ね合わせによる仮演出で、実際に食器を持ち替える連続作画は未制作です。002のスマホ画面の文章は調査欄で表現します。

音はWeb Audioの合成音です。生活音の質感と静寂の間を試すためのもので、実録の環境音や声優音声・笑い声の録音は未実装です。言葉や笑いの内容は字幕で伝えます。端末の低い音は、スピーカーによって聞こえ方が異なります。

ブラウザでの自動確認はChromiumで実施しました。Safari／iOS実機、VoiceOverなどでの最終確認、人物・小物の連続性を保つ本番アセット制作は今後の作業です。

## シナリオ・絵・音を変える

| ファイル | 役割 |
| --- | --- |
| `data.js` | プロローグ・案内・各履歴の文章、調査座標、再調査条件、必須断片、ヒント、結末 |
| `engine.js` | DOMに依存しない進行判定と保存。文章を変えるだけなら変更不要 |
| `main.js` | 画面描画と操作。`sceneEffects()`が仮の色・線のレイヤー |
| `style.css` | 受付機・紙の記憶画面・レスポンシブ・動き軽減 |
| `audio.js` | 仮SEと環境音。実音源を使う場合の差し替え先 |
| `assets/images/memories.png` | 2×2の記憶背景。左上001・右上002・左下003・右下004 |

各調査点の`base`が最初の反応、`variants[].when`が反応を変える前提断片、`grant`が再調査で得る断片です。通常の再調査はその場所を一度見ていることも条件になります。001の手のように前提が必要な箇所には`blocked`を設定します。`required`の断片が揃い、「閲覧を終える」を押した時点で次が解放されます。

調査位置`x`・`y`は絵の幅・高さに対する百分率です。背景を個別画像にする場合は`data.js`の`image`を変更し、`main.js`の背景サイズを`100% 100%`にします。画像とSVGの座標を揃えてください。進行データの互換性が変わる場合は保存キー／バージョンを更新するか、設定からリセットします。

## GitHub Pages

全て相対パスなので、リポジトリ名の付いたURLでも動きます。

**ビルドなし（推奨）**：Settings → Pages → Deploy from a branchで`main`ブランチと`/(root)`を選び、Saveを押します。Pagesの設定でプランによる制限が出る場合は、Settings → General → Danger Zone → Change repository visibilityでPublicに変更してから設定してください。通常、数分で上記の試遊URLから遊べます。

**GitHub Actionsを使う場合**：Settings → PagesのSourceをGitHub Actionsにし、付属の「Deploy browser prototype to GitHub Pages」を手動実行します。テスト→静的ファイルのビルド→`dist/`の配信を行います。自動pushトリガーは付けていません。ソース一式はGitHubへ反映しています。リポジトリの公開範囲とPagesの有効化は、GitHubの設定画面で管理します。

他の静的ホスティングでは、次で生成した`dist/`だけを配信できます。

```sh
npm test
npm run build
```

## 開発用の検証

`npm test`：解放順、001の再調査、24通りの初回調査順、任意調査を強制しないこと、保存の復元・破損・失敗などを5件のテストで確認します。

`npm run test:browser`：開発環境にPlaywrightとChromiumを用意し、先にローカルサーバーを起動して実行します。実行時依存には含めていません。`GAME_URL`（既定 `http://127.0.0.1:8000`）と`CHROMIUM_PATH`（既定 `/usr/bin/chromium`）で変更できます。4件の進行・両結末・再開・設定・キーボード・幅320/390/1365を確認し、`test-results/`へ画像を保存します。
